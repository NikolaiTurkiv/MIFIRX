Отчет
1. Цель работы
Целью работы является реализация собственной упрощенной библиотеки реактивных потоков на Java. В проекте реализованы базовые компоненты реактивного программирования, поддержка асинхронного выполнения, обработка ошибок, механизмы управления подписками и операторы преобразования данных.

В качестве основы использован паттерн «Наблюдатель» (Observer pattern), при котором источник данных отправляет события подписчику, а подписчик обрабатывает поступающие элементы, ошибки и завершение потока.

2. Общая архитектура решения
Реализация проекта построена вокруг класса MIFIObservable<T>, который представляет поток данных. Объект этого класса хранит логику подписки и умеет создавать новые потоки на основе уже существующих.

Основные компоненты системы:

MIFIObserver<T> — интерфейс наблюдателя с методами onNext, onError, onComplete.
MIFIObservable<T> — основной класс потока данных с методами create, subscribe, map, filter, flatMap, subscribeOn, observeOn.
MIFIEmitter<T> — внутренний интерфейс, через который источник отправляет элементы, сигнал ошибки и сигнал завершения.
MIFIDisposable — интерфейс управления подпиской, позволяющий отменить дальнейшее получение событий.
MIFICompositeDisposable — вспомогательный класс для группового закрытия нескольких подписок одновременно.
MIFIScheduler — интерфейс для выполнения задач в нужном потоке.
Структура реализации разделена на две основные части:

пакет org.example.mifi содержит ядро реактивной библиотеки;
пакет org.example.mifi.scheduler содержит реализации планировщиков выполнения.
3. Реализация базовых компонентов
3.1. Интерфейс MIFIObserver<T>
Интерфейс наблюдателя реализует три обязательных метода:

onNext(T item) — вызывается при поступлении нового элемента потока;
onError(Throwable throwable) — вызывается при возникновении ошибки;
onComplete() — вызывается при успешном завершении потока.
Таким образом, поток может передавать обычные данные, сигнал ошибки и сигнал завершения.

3.2. Класс MIFIObservable<T>
Класс MIFIObservable<T> является главным элементом библиотеки. Он создается через статический метод create(...), который принимает логику генерации событий.

Принцип работы:

При создании MIFIObservable в объект сохраняется функция подписки.
При вызове subscribe(...) создается внутренний Emitter.
Источник отправляет события через Emitter.
Emitter передает эти события подписчику.
Внутренняя реализация следит за тем, чтобы после завершения потока или после отмены подписки новые события больше не доставлялись.

3.3. Интерфейс MIFIDisposable
Для управления подпиской реализован интерфейс:

dispose() — отменяет подписку;
isDisposed() — показывает, была ли подписка отменена.
Это позволяет остановить поток данных до его естественного завершения.

4. Реализация операторов преобразования данных
4.1. Оператор map
Оператор map создает новый MIFIObservable, который подписывается на исходный поток и применяет к каждому элементу функцию преобразования.

Пример:

MIFIObservable.<Integer>create(emitter -> {
    emitter.onNext(1);
    emitter.onNext(2);
    emitter.onComplete();
}).map(item -> item * 10);
Результат работы такого потока: 10, 20.

4.2. Оператор filter
Оператор filter также создает новый поток, но пропускает дальше только те элементы, которые удовлетворяют условию.

Пример:

MIFIObservable.<Integer>create(emitter -> {
    emitter.onNext(1);
    emitter.onNext(2);
    emitter.onNext(3);
    emitter.onComplete();
}).filter(item -> item % 2 == 0);
Результат работы такого потока: только 2.

4.3. Оператор flatMap
Оператор flatMap преобразует каждый элемент исходного потока в новый MIFIObservable, после чего объединяет элементы внутренних потоков в один общий поток.

Пример:

MIFIObservable.<Integer>create(emitter -> {
    emitter.onNext(2);
    emitter.onNext(3);
    emitter.onComplete();
}).flatMap(item -> MIFIObservable.<String>create(emitter -> {
    emitter.onNext("value=" + item);
    emitter.onNext("square=" + (item * item));
    emitter.onComplete();
}));
Результат работы такого потока:

value=2
square=4
value=3
square=9
В реализации используется MIFICompositeDisposable, чтобы внешняя отмена подписки завершала и исходную, и внутренние подписки.

5. Обработка ошибок
В системе реализована передача ошибок через onError(...).

Ошибка может возникнуть в нескольких местах:

внутри исходного источника данных;
внутри map;
внутри filter;
внутри flatMap;
внутри внутренних потоков flatMap.
При возникновении ошибки поток считается завершенным. После этого новые элементы больше не доставляются. Такой подход упрощает поведение библиотеки и соответствует учебной задаче.

Если в onError(...) передается null, внутренняя реализация заменяет его на NullPointerException.

6. Реализация Scheduler и управление потоками выполнения
6.1. Интерфейс MIFIScheduler
Интерфейс MIFIScheduler содержит один метод:

void execute(Runnable task);
Он нужен для запуска задачи в определенном потоке или пуле потоков.

6.2. Реализованные Scheduler
В проекте реализованы три варианта Scheduler.

MIFIIOThreadScheduler
Использует CachedThreadPool.

Особенности:

хорошо подходит для задач ввода-вывода;
может создавать новые потоки по мере необходимости;
удобно использовать для большого количества коротких или ожидающих задач.
MIFIComputationScheduler
Использует FixedThreadPool.

Особенности:

подходит для вычислительных задач;
количество потоков ограничено;
снижает риск бесконтрольного роста числа потоков.
MIFISingleThreadScheduler
Использует один поток.

Особенности:

все задачи выполняются последовательно;
удобно, когда важно сохранить порядок обработки;
поведение проще отлаживать и анализировать.
6.3. Метод subscribeOn
Метод subscribeOn(scheduler) переносит сам запуск источника данных в указанный поток. Это означает, что логика создания и отправки элементов начинает выполняться не в текущем потоке, а в потоке выбранного Scheduler.

6.4. Метод observeOn
Метод observeOn(scheduler) переносит обработку элементов подписчиком в указанный поток. Это означает, что onNext, onError и onComplete будут вызваны в потоке выбранного Scheduler.

6.5. Различия между subscribeOn и observeOn
subscribeOn влияет на поток, в котором запускается источник;
observeOn влияет на поток, в котором обрабатываются события подписчиком.
Таким образом, можно разделить генерацию данных и их обработку между разными потоками.

7. Демонстрация использования
Пример использования библиотеки содержится в классе Main.

Упрощенный пример цепочки:

MIFIObservable<Integer> observable = MIFIObservable.create(emitter -> {
    emitter.onNext(1);
    emitter.onNext(2);
    emitter.onNext(3);
    emitter.onNext(4);
    emitter.onComplete();
});

observable
        .map(item -> item * 10)
        .filter(item -> item >= 20 && item < 40)
        .flatMap(item -> MIFIObservable.<String>create(emitter -> {
            emitter.onNext("value=" + item);
            emitter.onNext("double=" + (item * 2));
            emitter.onComplete();
        }))
        .subscribeOn(new MIFIIOThreadScheduler())
        .observeOn(new MIFISingleThreadScheduler())
        .subscribe(new MIFIObserver<String>() {
            @Override
            public void onNext(String item) {
                System.out.println(item);
            }

            @Override
            public void onError(Throwable throwable) {
                System.out.println(throwable.getMessage());
            }

            @Override
            public void onComplete() {
                System.out.println("completed");
            }
        });
Этот пример показывает:

создание потока;
преобразование данных через map;
фильтрацию через filter;
разворачивание вложенных потоков через flatMap;
перенос подписки в один поток;
перенос обработки в другой поток.
